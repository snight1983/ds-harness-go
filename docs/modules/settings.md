# 运行时设置

对应包：`settings`

## 定位

这套装置里有几十个模块，每个都带着几个旋钮：超时多少秒、默认用哪个模型、某个功能开不开。这些旋钮的值得有个统一的来路，否则只有两条退路，两条都不好走：

```mermaid
flowchart LR
    subgraph N1["写死在代码里"]
        A1["要改一个超时"] --> A2["改代码、重新发一次版"] --> A3["而它本来只是一个数"]
    end
```

```mermaid
flowchart LR
    subgraph N2["每个模块各存各的"]
        B1["配置界面要列出全部旋钮"] --> B2["得挨个模块去问"]
        B2 --> B3["没有一处地方能回答<br/>「这套装置一共有哪些旋钮」"]
    end
```

这个包是那条统一的来路：谁拥有哪一段配置、当前值是多少、谁能改、改完谁知道。

```mermaid
flowchart TD
    OWN["拥有者<br/>（某个模块）"] -->|"登记一段：这段归我，默认值是这些"| SVC["设置服务"]
    UI["配置界面"] -->|"读：现在都有哪些旋钮"| SVC
    UI -->|"写：把这个改成 90 秒"| SVC
    SVC -->|"改完了，新值是这个"| OWN
    SVC <-->|"存 / 取"| BK[("存储后端")]
```

## 架构

### 一个值是三层叠出来的

```mermaid
flowchart TD
    L1["① 类型默认值<br/>拥有它的那个模块写死的"] --> M["叠"]
    L2["② 组装层<br/>这次部署给的值"] --> M
    L3["③ 用户段<br/>人在配置界面上改的"] --> M
    M --> V["当前生效的值"]
    L3 -.->|"最上面，压得住下面两层"| M
```

三层各有各的作者，谁都不能替谁做主。压成一层的后果是「重置」这个动作没有落点：

```mermaid
flowchart LR
    subgraph BAD["只有一层"]
        A1["用户删掉自己那条覆盖"] --> A2["该退回到哪儿？"] --> A3["退回模块的默认值<br/>还是这次部署给的值？答不上来"]
    end
```

```mermaid
flowchart LR
    subgraph GOOD["三层分开交出去（当前做法）"]
        B1["配置界面看得见<br/>哪些格子是用户改过的"] --> B2["也就知道重置会退回哪一层"]
    end
```

「用户改过」这件事怎么判：**一个字段出现在用户那一层里，它就是被覆盖过的**。不需要拿值去和下层比。

### 一段配置只有一个主人

```mermaid
flowchart TD
    D[("存储里那份文档")] --> S1["一段：模型相关的旋钮"]
    D --> S2["一段：日志相关的旋钮"]
    D --> S3["一段：还没装上的某个模块的"]
    S1 --> O1["主人：模型那个模块"]
    S2 --> O2["主人：日志那个模块"]
    S3 -.->|"没有主人也不会被删掉<br/>那个模块装上来之后还得用"| S3
```

两个模块把同一段当成自己的，会立刻报错。这条不能宽容：

```mermaid
flowchart LR
    A["允许两个主人"] --> B["谁读到的都不完整"]
    B --> C["症状是「我明明配了，它没生效」"]
    C -.->|"而从配置那一头<br/>永远查不出这是重名"| C
```

### 存在哪儿：没有硬盘，也没有目录

```mermaid
flowchart TD
    Q["设置文档存哪儿"] --> N["不是本机的某个配置文件"]
    N -.->|"服务端没有硬盘<br/>也没有「目录」这个概念"| N
    Q --> Y["数据库，或者对象存储"]
    Y --> R["这样多个副本读到的是同一份"]
    Z["而这个包一台后端都不自带"] --> Z1["读、写、只不只读<br/>三件事由装配方递一个后端进来"]
```

不自带后端不是偷懒：桌面场景想落在本地、集群场景要落在数据库、有的部署整个是只读的——这三种在这个包眼里是同一个形状，分不开的只有装配方自己知道。

### 读的两条路

```mermaid
flowchart LR
    A["拥有者"] -->|"按自己那个类型读"| A1["拿到一个填好的值<br/>直接就能用"]
    B["配置界面、审计、协议层"] -->|"按原始形状读"| B1["拿到的是通用的键值结构"]
    B1 -.->|"它们本来就不知道<br/>每一段该是什么类型"| B1
```

## 写：三条路，各有各的用处

```mermaid
flowchart TD
    W["要改配置"] --> W1["合并一份补丁<br/>只提要改的键"]
    W --> W2["整段替换<br/>没提的键退回下面两层"]
    W --> W3["按路径改<br/>指名道姓改一个格子"]
    W2 -.->|"替换成空段<br/>就是把这一段整个重置"| W2
```

第三条路不是锦上添花，它是必需的：

```mermaid
flowchart TD
    A["配置界面手上的那份是脱敏的"] --> B["密钥字段按定义不在里面"]
    B --> C{"它要改一个普通字段"}
    C -->|"拿手上这份整段替换下去"| D["它从来没收到过的那些密钥<br/>会被一起删掉"]
    D -.->|"而全程不报任何错"| D
    C -->|"按路径只改那一个格子"| E["没提到的东西一律不动"]
```

### 一次写从头到尾

```mermaid
sequenceDiagram
    participant C as 调用方
    participant S as 设置服务
    participant B as 存储后端
    participant O as 拥有者与旁观者
    C->>S: 把超时改成 90 秒
    S->>S: ① 排进这一段的队，等前面的写完
    S->>S: ② 从「此刻」读这一段，不是从调用方看过的那份
    S->>S: ③ 核对修订号
    S->>S: ④ 叠三层，交给类型审一次
    S->>B: ⑤ 存下去
    B-->>S: 存好了
    S->>S: ⑥ 内存里那份跟着改
    S->>O: ⑦ 通知
```

次序里有三处是拿代价换来的：

```mermaid
flowchart TD
    A["先解析再落盘"] --> A1["校验没过时<br/>存储里一个字节都没动"]
    B["落盘成功就一定要认"] --> B1["否则「存储里是新的、内存里是旧的」<br/>这种分叉没有任何一方看得见"]
    C["读那一段在队列前端，不在调用时刻"] --> C1["前面那次写刚把它改掉<br/>这次就该基于改完的样子算"]
```

### 修订号：拦住基于过期快照的写

```mermaid
sequenceDiagram
    participant U1 as 配置界面 A
    participant U2 as 配置界面 B
    participant S as 设置服务
    U1->>S: 读，拿到修订号 7
    U2->>S: 读，拿到修订号 7
    U2->>S: 写（带 7），成功，现在是 8
    U1->>S: 写（带 7）
    S-->>U1: 拒绝：你读到之后它被改过了
    Note over U1: 重读一次再决定<br/>而不是把别人的改动盖掉
```

核对必须发生在队列前端，不能在调用那一刻：

```mermaid
flowchart LR
    A["在调用那一刻核对"] --> B["排在前面的写把这一段改掉之后"]
    B --> C["后面这个拿着旧快照的<br/>照样会通过"]
    C -.->|"那这道核对就等于没有"| C
```

### 修订号数的是存下来的那一段，不是生效值

```mermaid
flowchart TD
    A["用户存了一条<br/>和组装层一模一样的覆盖"] --> B{"算不算变了"}
    B -->|"看生效值"| C["没变，一个字节都没动"]
    B -->|"看存下来的那一段"| D["变了：这个字段从「继承来的」<br/>变成了「用户钉死的」"]
    D --> E["配置界面必须重读<br/>那个格子的标记要改"]
    E -.->|"所以这两件事的判定是分开的"| E
```

## 脱敏：能显示「已配置」，但从来不给出值

```mermaid
flowchart TD
    A["类型上把某个字段标成密钥"] --> B["脱敏这一趟"]
    B --> C["值被摘掉"]
    B --> D["位置被记下来<br/>并附一句：这个格子有没有值"]
    C --> E["配置界面渲染成一个只写的输入框"]
    D --> E
    E -.->|"能显示「已配置」<br/>又从来没收到过密钥本身"| E
```

```mermaid
flowchart LR
    A["任何要出这个进程的读"] --> B["必须走脱敏那一条"]
    C["原样返回那一条"] --> D["只留给同进程内的配置界面"]
    E["而脱敏不是加密"] -.->|"值本身怎么存<br/>是后端的事；真正的凭据<br/>该走凭据那条引用接缝，不整份写进配置"| E
```

有一个口子必须说清楚：密钥只有在类型明着声明的位置上才摘得掉。藏在一个没有形状的字段底下的密钥，这一趟走不进去，也就摘不掉——所以不要那样建模。

## 有人绕过这个包直接改了存储

```mermaid
flowchart TD
    A["后端发现存储上的文档变了"] --> B["把整份交回来重新叠一遍"]
    B --> C{"逐段解析"}
    C -->|"这一段解得开"| D["换新值，通知它的主人"]
    C -->|"这一段被人手工编辑坏了"| E["保留上一个好值，记一条日志"]
    E -.->|"一段坏了不该<br/>把所有跑着的模块一起拖死"| E
    C -->|"这一段没有主人"| F["原样留在文档里，不动"]
```

## 生命周期与并发

```mermaid
flowchart TD
    A["服务起来时先把文档读进来<br/>再交给别人用"] --> A1["否则第一个登记方拿到的是默认值"]
    A1 --> A2["然后被一次「变更」悄悄换掉<br/>——一个没人改过的启动过程里凭空多出一次变更"]
    B["关闭"] --> B1["不再收新的写<br/>等在途的那些走完"]
    C["注销一段之后"] --> C1["它就不能再被写了<br/>而且注销认的是这一次登记本身"]
    C1 -.->|"重复注销不会把继任者摘掉"| C1
```

```mermaid
flowchart LR
    A["同一段上的写是串行的"] --> B["不同段之间互不挡着"]
    C["通知是就地同步发的"] --> D["调用顺序就是提交顺序"]
    D -.->|"代价：一个慢的观察者<br/>会把整条提交路径拖住"| D
    E["所以观察者的约定是<br/>不许阻塞、不许回头调写"] --> D
```

```mermaid
flowchart TD
    A["读到的值是只读的"] --> B["标量各是各的"]
    A --> C["里面的列表和键值结构是共享的"]
    C -.->|"改它们会影响每一个读到过这个值的人"| C
    D["没有为每次读做一份深拷贝"] --> E["生效值在两次提交之间根本不变<br/>而读落在每一次操作的路径上"]
```

还有一条检查一直挂在提交路径上，它查的是通知本身说的话成不成立：

```mermaid
flowchart TD
    N["一条「已提交」的通知"] --> Q1["服务还活着吗"]
    N --> Q2["这一段此刻还有主人吗"]
    N --> Q3["通知里的值就是服务此刻的权威值吗"]
    N --> Q4["生效值真的变了吗"]
    Q3 -.->|"对不上意味着通知和状态分了叉<br/>而收到通知的一方会照着通知走"| Q3
    Q4 -.->|"一次「其实没变」的通知<br/>会把「变更」这个词的含义稀释掉"| Q4
```

## 失败语义

```mermaid
flowchart TD
    A["出了岔子"] --> B{"哪一类"}
    B -->|"段名不合法 / 重名登记 / 这一段没有主人"| C["当场拒绝<br/>不留下半个状态"]
    B -->|"叠出来的值类型对不上，或过不了主人自己的检查"| D["这次写不成立<br/>调用方当场就知道，而不是存下一个会让主人失能的值"]
    B -->|"修订号对不上"| E["拒绝，要求重读<br/>绝不自动覆盖"]
    B -->|"后端是只读的"| F["当场拒绝<br/>不能写完了不生效"]
    B -->|"落盘失败"| G["内存里那份保持旧值"]
    B -->|"某个观察者自己炸了"| H["其余观察者照样跑到<br/>已经落盘的写不因此报失败"]
```

两条各补一句：

```mermaid
flowchart LR
    A["只读后端上的写要当场拒"] --> B["写完了不生效的症状是<br/>「我改了但它没变」"]
    B -.->|"而用户没有任何理由<br/>怀疑是存储不收"| B
    C["一个观察者炸掉不许掐断后面的"] --> D["变更已经提交了"]
    D --> E["没跑到的那几个从此和存储不一致<br/>而它们永远不会知道"]
```

## 能力边界

```mermaid
flowchart TD
    Y["这个包做的"] --> Y1["按段登记、三层叠加、算出生效值"]
    Y --> Y2["三条写入路径，加上修订号这道乐观并发"]
    Y --> Y3["脱敏展示，和变更通知"]
    N["不做的"] --> N1["不自带任何存储后端<br/>文件、数据库、远程配置都由装配方递进来"]
    N --> N2["不加密<br/>脱敏只保护展示这条路"]
    N --> N3["不解释形状描述<br/>原样搬给配置界面，也不替登记方生成一份"]
    N --> N4["不提供跨进程共识<br/>队列只串本进程的写，跨副本挡不挡得住取决于后端"]
    N --> N5["不替主人定义业务上的合理性<br/>类型对不对由解码判，值合不合理由主人自己判"]
```

建在它上面的部署级默认模型选择另有一篇：[部署级默认模型](agentdefaultmodel.md)。
