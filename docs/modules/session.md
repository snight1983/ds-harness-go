# Session

覆盖会话事件、活会话、持久化、当前状态、状态缓存、查询、统计、标题和遥测。

## 定位

Session 模块保存 Agent 运行的长期事实，并把这些事实转换成运行时和界面需要的当前状态。

项目把会话拆成两层：

| 包 | 职责 |
|---|---|
| `session` | 事件、负载、会话头、日志校验和纯计算，不持有活对象 |
| `core/session` | 活 `Session`、`Store`、事件追加、创建、恢复和分叉 |

持久化、查询、统计等模块只依赖 `session` 的值和规则，不需要依赖活会话注册表。

## 事件日志

事件日志按顺序记录“发生过什么”。核心事件包括：

- 回合开始与结束。
- 步骤开始与结束。
- 用户消息。
- 模型流式分块和完整回复。
- 工具调用与工具结果。
- Context 快照和压缩检查点。

扩展模块通过 `EventTypes` 声明自己的事件类型，再加入 `Vocabulary`。未知且不可忽略的事件会阻止日志恢复，避免旧程序静默误读新语义。

每条事件具有 Session 内连续的 `Seq`。事件负载使用稳定 JSON，写入前校验，读取时保留不认识但允许透传的数据。

## 当前状态

事件日志只保存动作，程序还需要直接读取“现在是什么”。例如：

```text
历史记录                              当前状态
-------------------------------      ----------------------
用户消息、模型分块、完整回复    ->    当前模型可见历史
Inbox 插入和认领                ->    当前待处理消息
每次模型请求的用量              ->    当前 Token 统计
标题更新记录                     ->    当前会话标题
```

源码把“根据事件记录整理出的当前状态”称为 `projection`。它是固定 Go 代码的确定计算，不是让模型分析聊天内容。

同一份合法日志和同一版本的规则必须得到同样的结果。

## 当前状态注册表

`session/projection.Registry` 管理多个独立的状态计算单元。每个单元声明：

- 唯一键。
- 状态格式版本。
- 初始状态。
- 如何把一条事件应用到状态。
- 如何编码和恢复检查点。

典型单元包括 Todo、Goal、Plan Mode、统计和标题。一个单元不认识某条事件时保持原状态。

读取分三级：

| 方式 | 数据来源 | 用途 |
|---|---|---|
| 活会话 Snapshot | 内存中的完整事件 | 当前请求和实时界面 |
| Checkpoint View | 已有检查点 | 零 I/O 快速读取 |
| Restore | 检查点加事件尾部 | 冷启动和恢复 |

## 状态缓存

`session/projectioncache` 保存状态计算检查点，避免长会话冷启动时从第一条事件重新处理。

- 会话运行中，状态在内存里增量更新。
- 回合结束、事件数达到阈值或时间达到阈值时写缓存。
- Session Detach 时同步写最后一次检查点。
- 冷启动读取“缓存检查点 + 缓存之后的事件”。
- 缓存缺失、损坏、版本变化或绑定到另一段日志时，退回完整重算。
- 缓存写失败只影响下次恢复速度，不改变已提交事实。

写缓存前必须先把对应事件真正落盘。缓存可以落后，不能领先。

## 活 Session

`core/session.Session` 是可追加事件的活对象，`Store` 管理进程内活会话。

主要能力：

- `NewSession` 和 `RestoreSession` 创建内存对象。
- `Session.Append` 追加并发布一条事件。
- `Store.Prepare` / `PrepareRestored` 准备尚未公布的会话。
- `Store.Enter` / `Announce` 分离登记与公布。
- `Store.Create` 完成普通登记流程。
- `Store.Fork` / `ForkByID` 创建合法的历史前缀分叉。
- `Store.Get` / `List` 查询活会话。
- Created、Disposed、Event、Flush Observer 扩展生命周期。

Session ID 与 Agent ID 在运行时必须一致。

## 写入规则

- 单个 Session 只允许一个事件写者，正常写者是对应 Agent Loop。
- Append 会拒绝并发或 Observer 回调中的重入追加。
- 事件先进入 Session，再在锁外通知 Observer。
- 交给外部的事件切片是副本；调用方应视为只读。
- 日志校验检查序号、回合/步骤配对、工具调用配对和事件负载。
- 进程内对象不能绕过 Append 直接改日志。

## 创建、恢复与分叉

### 创建

新会话包含 ID、创建时间、工作目录、父会话、Seed 长度、Origin、委派深度和 Agent Preset 等头信息。

### 恢复

恢复读取持久化头和事件，完成格式、词汇和结构校验，然后重建活 Session。无法解释的必需事件、破损尾部或身份不一致必须明确处理。

### 分叉

分叉只接受从 Seq 0 开始、连续、回合完整的历史前缀。不能在打开的回合、步骤或悬空工具调用中间切断。新会话记录父 Session 与 Seed 边界，但运行期 owner 可以不同。

## 持久化

`session/persistence` 定义会话存档结构、`Store` / `Backend` 接口和独立的 `WriteBehind` 队列：

- 创建持久化会话头。
- 追加 Seq 连续的事件批次。
- 从指定 Seq 读取尾部。
- 读取、检查和列举会话存档。
- 使用 revision 判断存档是否发生变化。
- Write-behind 队列、节流、Flush 和关闭排空。
- 校验并修复可安全判断的崩溃尾部。

当前包没有提供监听活 Session 并自动完成 Create、Append、Flush、Detach 的顶层 PersistenceCoordinator，也没有内置生产会话后端。宿主必须完成这层接线，并提供满足 `core/agentloop.SessionPersistence` 的 `Prepare` / `List` 适配。持久化原语不解释模型、工具或业务事件的业务含义。

## 检查点策略

`session/checkpointpolicy` 在三处副作用边界安装耐久屏障：模型请求发出前、顶层工具调用执行前、每个步骤开始前。Flush 失败会阻止对应模型请求、工具或步骤继续，避免外部副作用发生后日志仍未落盘。嵌套工具调用复用外层屏障，不重复 Flush。该策略不拥有存储后端，也不负责状态缓存的数量和时间节流。

## 查询

`sessionquery` 提供会话和事件查询：

- 查询活会话与已持久化会话。
- 按 ID、父会话、工作目录、创建时间和可用性过滤。
- 搜索事件文本、类型、Seq 和时间。
- 读取当前表面或原始事件。
- 追踪事件上下文和会话血统。
- 对多会话执行受控并发的状态计算。

`sessionquery/querytool` 把受授权的查询能力暴露给模型。宿主必须提供权限检查，不能让模型凭 Session ID 越权读取。

## 统计、标题和遥测

| 包 | 能力 |
|---|---|
| `session/stats` | 统计 Turn、Step、消息、Token 和运行结果 |
| `session/sessiontitle` | 从事件维护规范化标题状态 |
| `session/sessiontitlellm` | 使用模型生成标题的提供方 |
| `session/telemetry` | 采集、脱敏并把记录交给宿主 Sink；批处理与重试由 Sink 负责 |

这些能力读取同一份事件事实，但各自维护独立的当前结果和生命周期。

## 并发

- `Session` 与 `Store` 各自有锁，但不会同时持有两把锁调用外部代码。
- Observer 在锁外运行。
- 写后持久化和状态缓存可在后台运行，但必须维护事件水位。
- 会话 Store 负责事件追加契约；状态缓存使用自己的 `storage/domain` 写链，两者不是同一个 Backend。
- Flush 是耐久屏障，不等于普通内存更新。

## 边界

Session 模块负责：

- 事件格式、校验和活会话。
- 创建、恢复、分叉和生命周期通知。
- 持久化接口与写后原语、状态计算、缓存、查询、统计、标题和遥测。

Session 模块不负责：

- 决定模型如何回答或工具如何执行。
- 用户鉴权和租户权限。
- 提供具体 HTTP API。
- 把状态缓存当成权威数据。
- 自动修复所有语义损坏；不可安全判断时必须失败。
