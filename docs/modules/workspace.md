# Workspace

对应包：`feature/workspace`

## 定位

会话攒到第三十条的时候，人就找不着东西了：

```mermaid
flowchart LR
    subgraph N["没有工作区"]
        A1["会话 1"] --> A2["会话 2"] --> A3["……"] --> A4["会话 37"]
        A4 --> A5["一条平铺的长列表<br/>哪几条是同一个项目的<br/>只能挨个点开看"]
    end
```

```mermaid
flowchart LR
    subgraph Y["有工作区"]
        B1["结算系统"] --> B2["它底下的 12 条会话<br/>次序由人手排"]
        B3["风控模型"] --> B4["它底下的 9 条"]
        B5["写周报"] --> B6["它底下的 3 条"]
    end
```

这个包就是那本**登记册**。一个工作区身上只有三样东西：

```mermaid
flowchart TD
    W["一个工作区"] --> A["① 它指着的那个位置<br/>一个不透明标识"]
    W --> B["② 一个给人看的标题"]
    W --> C["③ 一串会话，次序由人手排定"]
    N["它不是一个容器"] -.->|"删掉这条登记：那个位置还在<br/>会话日志一条不少"| W
```

### 「工作区」不是你电脑上的一个文件夹

这是整篇里最容易想歪的一处，而想歪了会一路错到底：

```mermaid
flowchart TD
    A["直觉：工作区 ＝ 硬盘上的一个目录"] --> B{"服务端有硬盘吗"}
    B -->|"没有。这是既定前提"| C["存储全走数据库和对象存储<br/>为的是能多副本部署"]
    C --> D["所以工作区指着的不是目录<br/>是存储接缝交出来的一个不透明标识"]
    D --> E["不许解析、不许拼接、不许当路径用"]
```

于是「身份」和「给人看的那条路径」被拆成两样，谁也不冒充谁：

```mermaid
flowchart LR
    A["同一个位置<br/>可能有好几种写法"] --> B["存储接缝负责<br/>把它们归到同一个标识上"]
    B --> C["身份：拿来比的那一个<br/>两个工作区不许指着同一个"]
    B --> D["展示路径：给人看的那一条<br/>建的时候盖上，之后再也不重写"]
    D -.->|"位置不见了也不重写它"| D
```

DSH 那份 TypeScript 代码里这两样是同一个字段，因为它的身份就是一条本机绝对路径：

```mermaid
flowchart LR
    subgraph DSH["DSH 的做法"]
        A1["身份 ＝ 那条本机绝对路径"] --> A2["每次比之前<br/>先算一遍真实路径<br/>再确认它确实是个目录"]
    end
    subgraph GO["这里的做法"]
        B1["身份 ＝ 存储接缝给的标识"] --> B2["比一次相等就完了<br/>一次存储调用都不发"]
    end
    A2 -.->|"一条本机路径只在那一台机器上有意义<br/>它会把一个会话钉死在一台机器上"| B1
```

代价要写明白：这个标识是**存进介质**的，所以它对后端多了一条要求——同一个位置的标识必须跨进程重启保持不变。一个每次现分配的临时编号不满足；配上这样的后端，重启之后整册工作区会认不出自己指着哪儿。


### 一个会话算不算这个工作区的

```mermaid
flowchart TD
    Q["判据有两条"] --> C1["① 它的编号在这条记录的候选账目里"]
    Q --> C2["② 它自己的会话头点名的就是这个工作区"]
    C1 --> AND{"两条同时成立才算"}
    C2 --> AND
    AND -->|"成立"| YY["列出来"]
    AND -->|"只占一条"| NN["这一次不列<br/>但**不**立刻抹掉"]
    NN -.->|"那条会话头可能只是这一刻还没被列举到"| NN
```

筛不出来的候选什么时候才真的删掉：

```mermaid
flowchart LR
    A["读的时候"] --> B["只是不交出去，账目一个字不动"]
    B --> C["等这个工作区下一次真的发生写入"]
    C --> D["顺手裁掉，读和写用的是同一条判据"]
    A -.->|"读一次就删一条的话<br/>一次列举延迟就会永久删掉一条真会话"| D
```

两处必须是同一条判据——否则读出来的和存下去的会慢慢分叉。

## 建一个工作区要改两处，中间可能断电

一次建工作区落两笔：表里那条记录，和全局槽里的次序。两笔之间机器没了，介质上就会出现「有记录没次序」或者反过来。

```mermaid
sequenceDiagram
    participant R as 登记册
    participant D as 介质
    R->>D: ① 先写一句「我正在建 X」
    R->>D: ② 写记录 X
    R->>D: ③ 把 X 插进展示次序，并抹掉那句话
    Note over R,D: ① 之后任何一步断掉<br/>介质上都留着「谁没做完」这句话
```

```mermaid
flowchart TD
    S["下次启动"] --> Q{"介质上留着那句话吗"}
    Q -->|"留着：上次建到一半"| A["把那条没进次序的孤儿记录删掉"]
    Q -->|"留着：上次删到一半"| B["把那次删除做完"]
    Q -->|"没留，但次序和表对不上"| C["报错，一个字都不改"]
    C -.->|"猜一次「大概本来该是什么样」<br/>会把一次可查的事故<br/>变成一份看上去正常的坏数据"| C
```

它**绝不**从一条记录的样子去倒推它当初是怎么来的。能被解释的分叉由那句话明确点名，剩下的一律大声报出来。

## 一次读回全部字段，还是分六次读

逐字段读之间**没有原子性**。别人的写可以夹在两次读中间：

```mermaid
sequenceDiagram
    participant U as 界面
    participant D as 介质
    participant W as 另一台副本
    U->>D: 读标题
    D-->>U: 旧标题
    W->>D: 改标题，再挂一个会话
    U->>D: 读会话列表
    D-->>U: 已经带上新会话了
    Note over U: 手里这份 ＝ 旧标题 ＋ 新会话列表<br/>而这一种组合，介质上从来没有出现过
```

```mermaid
flowchart LR
    A["一次读回全部字段"] --> B["六个字段来自同一个修订"]
    B --> C["界面上不会出现<br/>新标题配着旧会话列表"]
    D["它**不含**「那个位置还在不在」这一位"] -.->|"那一位要另外问一次存储<br/>混进来就是拿第二次往返的答案<br/>冒充同一时刻的事实"| D
```

它只管**一个**工作区。连着读两个工作区仍然是两次读，中间照样可以夹着别人的写。

### 「那个位置还在不在」单独问

```mermaid
    B -->|"不存在 / 不是一个目录 / 后端答不上来"| C["一律答「用不了」"]

    C -.->|"绝不因此改动那条记录<br/>位置可能只是被临时移走了"| C
```

## 那条运行期不变量：有人绕过登记册直接写

```mermaid
flowchart TD
    A["有人绕过登记册<br/>直接往工作区记录表里写一条"] --> B["写进去的记录<br/>和展示次序、和归属账目各说各话"]
    B --> C["而没有任何一步会报错"]
    C --> D["所以它值得一条运行期不变量"]
```

判据是「记账」而不是「回头核对」：

```mermaid
        A1["别的副本完全可以合法地<br/>插在这次提交和这次核对之间"] --> A2["读回来的和变更对不上"]
        A2 --> A3["误报"]
        A3 -.->|"一条会误报的检查比没有检查更糟<br/>它教会所有人忽略它"| A3
    end
```

```mermaid
flowchart LR
    subgraph GOOD["只认自己记的那一笔（当前做法）"]
        B1["每次登记册发起的写都记一笔<br/>变更是在写的过程里同步发的<br/>所以那笔账必然还举着"] --> B2["一条针对这张表、<br/>而账上查无此人的变更<br/>只可能来自一次绕过"]
```

## 生命周期与并发

```mermaid
stateDiagram-v2
    [*] --> 打开中: Open
    打开中 --> 可用: 收完上次没做完的那句话 → 校验介质 → 必要时收编一次历史
    打开中 --> [*]: 中途失败就把已经开出来的域关掉
    可用 --> 可用: 每次操作之前，先把上次遗留的那句话收掉
    可用 --> 已关闭: Close
    已关闭 --> 已关闭: 再关一次是空操作
```


## 失败语义

```mermaid
flowchart TD
    A["出了岔子"] --> B{"哪一类"}
    B -->|"路径解析不出来 / 不是一个目录"| C["这条路径不能拿来建工作区"]
    B -->|"要挂上来的会话过不了归属判据"| D["拒绝，且一个字不写"]
    B -->|"挪位点名了一个不在列表里的锚点"| E["拒绝，且一个字不写"]
    B -->|"这个句柄指着的记录已经被别人删了"| F["单独一种：「这个工作区没了」"]
    B -->|"介质自相矛盾，且没有那句话解释得了"| G["报错，绝不猜着修"]
    B -->|"数据库、存储、会话仓库自己出故障"| H["原样报出来"]
    F -.->|"折进上面那两类<br/>会让一次正当的删除读起来像一场事故"| F
    H -.->|"绝不塌成「这个会话不存在」<br/>否则一次掉线会变成一次拒绝归档"| H
```

```mermaid
flowchart LR
    A["落盘失败"] --> B["介质不改，变更也不发"]
    C["善后也失败了"] --> D["原本那条失败和善后那条一起交出去"]
    D -.->|"谁都不许被另一个盖掉"| D
```

## 能力边界

```mermaid
flowchart TD
    Y["这个包做的"] --> Y1["记「哪些会话属于哪个位置」"]
    Y --> Y2["记一份人手排定的次序，和一份归档集合"]
    Y --> Y3["断电之后把没做完的那次写收干净"]
    N["不做的"] --> N1["不建目录、不动代码仓库<br/>删掉一条登记，会话日志一条不少"]
    N --> N2["不做路径规范化<br/>「同一个位置的两种写法」由存储接缝回答"]
    N --> N3["不提供用户、团队或者权限模型<br/>谁能看、谁能改，不在这里回答"]
    N --> N4["不实现自己的存储<br/>会话仓库只用来确认归属，不是它的数据库"]
    N --> N5["不做断线重连的增量传输<br/>重连就重取整值"]
    N --> N6["不承诺跨工作区的一致读<br/>连着读两个仍然是两次读"]
```
