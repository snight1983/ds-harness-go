# 大结果外置

对应包：`spill`、`feature/spillpolicy`、`adapter/textstore`

## 定位

工具是会吐出巨物的。抓一个网页回来两百 KB，列一遍构建产物三千行，查一次数据库几万条记录。这些东西**原样塞进模型的上下文**，会一次吃掉本来能装下几十轮对话的额度。

```mermaid
flowchart LR
    subgraph N["原样塞进去"]
        A1["工具吐出两百 KB"] --> A2["整段进上下文"] --> A3["额度见底<br/>前面几十轮被挤掉"]
        A3 --> A4["模型开始忘事"]
    end
```

另一种偷懒的做法更糟：直接截断，只留前面一小段。

```mermaid
flowchart LR
    subgraph C["静默截断"]
        B1["工具吐出两百 KB"] --> B2["只留前 2 KB"] --> B3["剩下的没了"]
        B3 --> B4["模型以为自己看到的是全部<br/>然后基于半份东西下结论"]
    end
```

这三个包做的是第三条路：**全文挪到别处存着，原地留一段预览、一个句柄、一句「怎么把它取回来」**。

```mermaid
flowchart LR
    subgraph S["外置"]
        C1["工具吐出两百 KB"] --> C2["全文存进外部存储"]
        C2 --> C3["原地留下：<br/>开头一截 ＋ 结尾一截<br/>丢了多少字节<br/>句柄<br/>怎么取回来"]
        C3 --> C4["模型知道有东西被挪走了<br/>也知道去哪儿找"]
    end
```

关键差别只有一句：**模型必须知道内容被移走了**。截断是骗它，外置是告诉它。

## 架构

```mermaid
flowchart TD
    TOOL["一件工具跑完了<br/>结果是一大段文字"] --> POL["feature/spillpolicy<br/>判断超没超预算"]
    POL -->|"没超"| KEEP["原样交出去"]
    POL -->|"超了"| SEAM["spill<br/>那条只有一个动作的接缝"]
    SEAM --> IMPL["adapter/textstore<br/>本仓库唯一那份实现"]
    IMPL --> FS["文件系统接缝"]
    FS --> OSS["对象存储<br/>（服务端部署）"]
    FS --> DISK["本机磁盘<br/>（开发机）"]
    IMPL -->|"句柄 ＋ 精确字节数 ＋ 取回说明"| POL
    POL --> REPL["拼出替换文字<br/>交给模型"]
```

三个包各管一段，边界卡得很死：

| 包 | 它管的 | 它明确不管的 |
|---|---|---|
| `spill` | 一个动作的约定：交出全文，换回句柄 | 什么时候该外置、内容留多久、怎么读回来 |
| `feature/spillpolicy` | 多大算大、挪走之后原地留什么话 | 全文存到哪儿、怎么切预览 |
| `adapter/textstore` | 起名、归拢、不覆盖地写下去 | 判断该不该写、取回、清理 |

### 这条接缝只能写，没有读

```mermaid
flowchart LR
    A["交出全文"] --> B["换回一个能给模型看的名字"]
    C["读回来"] -.->|"这里根本没有这个方法"| B
    B --> D["模型照着取回说明<br/>去调宿主自己的别的工具"]
```

**为什么不加一个读**：加上去，这条接缝就变成了第二套存储——而每个后端本来就各自有自己的读取通道（对象存储有它的 SDK，检索系统有它的查询）。多一个读方法，等于要求每个后端把自己已有的读能力再从这个洞里穿一遍。

### 句柄一律不解析

```mermaid
flowchart TD
    L["句柄是后端自己定的一串字符"] --> L1["本机后端：可能是一条路径"]
    L --> L2["对象存储后端：可能是一个对象键"]
    L --> L3["数据库后端：可能是一行的主键"]
    L1 --> USE["拿到它的人只做一件事：<br/>连同取回说明一起渲染给模型看"]
    L2 --> USE
    L3 --> USE
    X["解析它 / 拼接它 / 推断它长什么样"] -.->|"一律不许"| USE
```

## 全文落到哪儿去：不是临时文件

这一节是本篇和 DSH 分岔最大的地方。

```mermaid
flowchart TD
    subgraph D["DSH 的做法（桌面工具）"]
        D1["系统临时目录"] --> D2["按会话建一个 0700 的子目录"]
        D2 --> D3["产物文件权限 0600"]
        D3 --> D4["句柄就是那条本机路径"]
    end
```

这套办法在一台开发者自己的机器上完全正确。放到本仓库要服务的形态上，它每一条前提都不成立：

```mermaid
flowchart LR
    A["这台服务没有硬盘"] --> A1["临时目录不存在"]
    B["也没有目录这个概念"] --> B1["0700 / 0600 这些权限位没有对应物"]
    C["要多副本部署"] --> C1["A 副本写下的文件<br/>B 副本读不到"]
    C1 -.->|"于是模型拿到一个句柄<br/>换台机器就打不开"| C1
```

所以 `adapter/textstore` 换的是介质，不是语义：

```mermaid
flowchart TD
    TS["adapter/textstore"] --> SEAM["它只用三个原语：<br/>解析路径、建一层、不覆盖地写"]
    SEAM --> FSI["文件系统接缝"]
    FSI --> P1["对象存储后端<br/>「建一层」在这里如实什么都不做"]
    FSI --> P2["本机磁盘后端<br/>（开发和测试）"]
    NOTE["换介质是装配时的一行配置"] -.->|"业务代码一行不动"| TS
```

「起名和归拢」这套办法照其原样取自 DSH 那个本机实现；换掉的只是它落到哪儿。

### 一个键分三段，每段各有各的活

```mermaid
flowchart LR
    R["根前缀<br/>（装配时给）"] --> S["session-＋会话 id 的哈希前 12 位"]
    S --> N["16 位随机十六进制"]
    N --> M["净化过的建议名"]
    S -.->|"按会话归拢"| S
    N -.->|"不撞名的唯一来源"| N
    M -.->|"只是给人看的尾巴"| M
```


### 建议名永远不是路径

```mermaid
flowchart TD
    A["建议名一路来自工具名"] --> B["而工具名可以由插件自定"]
    B --> C{"直接当路径片段用"}
    C -->|"会发生什么"| D["一个插件起名叫「../../别处」<br/>就写到别人家去了"]
    C -->|"当前做法"| E["先净化：只留字母、数字、点、下划线、连字符<br/>其余一律换成下划线"]
    E --> F["拼不出分隔符<br/>而且前面永远缀着那 16 位随机码<br/>所以它也不可能是「上一层」"]
    F --> G["穿越在构造上就不成立"]
```

DSH 那边这一段做的是**可逆**编码，能从键反推回原来那个名字。这里故意不要可逆——没有任何一条路需要反推，而不可逆的映射让净化后的名字读起来更像原来那个。至于会不会撞名，那是随机那一段的活，不是这一段的活。

### 撞名就报错，绝不覆盖

```mermaid
flowchart LR
    A["写入走「不存在才写」"] --> B{"撞上了吗"}
    B -->|"没撞（几乎总是）"| C["写下去"]
    B -->|"撞了"| D["报错"]
    D -.->|"16 位随机码撞上是天文数字分之一<br/>真撞上说明介质出了问题"| D
    E["静默覆盖"] -.->|"会毁掉在先那份产物"| F["而上层之所以敢把结果挪走<br/>依据正是「挪走的那份还在，一个字都没少」"]
```

同一条道理的另一半：取不到随机字节的时候**不写**。退回一个猜得出来的名字，等于让后来的一次写有机会顶掉在先那一份。

### 取回说明由装配方给，不写死

```mermaid
flowchart TD
    A["「怎么把它读回来」这句话"] --> B{"谁知道答案"}
    B --> C["取决于装的是哪条文件系统<br/>——句柄是路径还是对象键"]
    B --> D["取决于这套部署里有哪些工具<br/>——本仓库不提供读文件的工具"]
    C --> E["所以它是一项配置"]
    D --> E
    F["写死一句「用 read 工具打开这条路径」"] -.->|"DSH 敢这么写<br/>是因为它两条都知道"| E
```

### 不做启动清扫

```mermaid
flowchart TD
    A["DSH 那边：启动时扫一遍根<br/>把超期的产物删掉"] --> B{"这里为什么不做"}
    B --> C["文件系统接缝上没有<br/>「按修改时间扫一棵树」这个原语"]
    C --> C1["真要做就是逐层列举再逐个查<br/>在对象存储上等于一次全量列举"]
    B --> D["多副本部署下每个副本<br/>都会去扫同一棵树"]
    D --> D1["而清扫和别的副本此刻正在写的产物之间<br/>没有任何协调"]
    E["保留期交给介质自己"] --> E1["对象存储有生命周期规则"]
    E --> E2["本机磁盘有运维的定时任务"]
    E1 -.->|"两者都比一次启动时的尽力而为靠谱"| E
    E2 -.-> E
```

## 策略：什么时候动手，动手之后留什么话

### 一次判断的全过程

```mermaid
flowchart TD
    A["一件工具跑完了"] --> B["先让链上后一环把结果定下来"]
    B --> C{"这份裁决轮得到我换吗"}
    C -->|"轮不到"| KEEP["原样交出去"]
    C -->|"轮得到"| D{"内容是不是全都是纯文字"}
    D -->|"混着图片或别的块"| KEEP
    D -->|"是"| E{"字节数超过上限了吗"}
    E -->|"没超"| KEEP
    E -->|"超了"| F["存全文，拼替换文字"]
    F --> G{"拼成了吗"}
    G -->|"成了"| H["交出替换文字"]
    G -->|"没成"| KEEP
```

**为什么先让后一环定下来再判**：这一层约束的是**最终会呈现给模型的那份东西**。工具自己那些特有的加工先跑完，然后才轮到这条通用的封顶；一个被别人换过内容的结果，换上去的那份同样会被封顶。

### 四种轮不到它换的情况

```mermaid
flowchart TD
    S{"轮不到换的四种"} --> S1["这次调用被拦下了<br/>交出去的是纠正性反馈，不是工具结果"]
    S --> S2["裁决换的是「值」<br/>换值要回注册表重新验、重新渲染<br/>和换内容在同一次裁决里互斥"]
    S --> S3["这是一次嵌套的子派发<br/>由它外层那次调用统一外置"]
    S --> S4["这件工具叫 read"]
    S3 -.->|"单独换掉子结果<br/>外层拿到的就是一份缺了一块的东西"| S3
```

### 为什么单独放过 read

## 上限是**替换之后**的上限

这是这一层最容易写错、也最要紧的一条，所以单开一节。

```mermaid
flowchart TD
    subgraph BAD["天真的做法"]
        A1["拿满上限切一段预览"] --> A2["再把那句说明接在后面"]
        A2 --> A3["替换出来的东西比上限大"]
        A3 --> A4["对一份刚刚超标的结果<br/>甚至比原文还大"]
        A4 --> A5["为了省上下文而多花上下文"]
    end
```

```mermaid
flowchart TD
    subgraph GOOD["当前做法"]
        B1["先按最坏情况给那句说明留出位置"] --> B2["预览只能用剩下的那点预算"]
        B2 --> B3["预览 ＋ 空行 ＋ 说明<br/>合起来一定在上限之内"]
    end
```

「最坏情况」怎么估：那句说明里唯一会变长的是「丢了多少字节」这个数，于是拿「全丢」去估它——真实的丢弃数一定不大于全文字节数，位数也就不会更多，留出来的位置一定够。

### 剩下的预算怎么分给预览

```mermaid
flowchart LR
    A["剩余预算"] --> B["对半分"]
    B --> C["头：一半，多出来的那个字节归它"]
    B --> D["尾：一半"]
    C -.->|"一份结果的开头<br/>通常比结尾更能说明它是什么"| C
```

### 连说明都塞不下的时候，不换

```mermaid
flowchart TD
    A["上限给得极小<br/>或者后端的句柄特别长"] --> B["拼出来的替换文字还是超过上限"]
    B --> C["放弃这次外置，原样保留内联内容"]
    C -.->|"换了就破了「上限」这个承诺"| C
    D["全文已经写下去了怎么办"] --> E["它是一份无害的孤儿<br/>清理归介质自己的保留期管"]
```

## 尽力而为：绝不把一次成功的调用变成失败

```mermaid
flowchart TD
    X{"三件可能出岔子的事"} --> X1["这次调用没有会话归属"]
    X --> X2["后端存不下（没权限、盘满、连不上）"]
    X --> X3["说明本身就超过了上限"]
    X1 --> Y["处置全都一样：<br/>记一条日志，原样把内联结果交出去"]
    X2 --> Y
    X3 --> Y
    Y -.->|"绝不判成工具失败"| Y
    Z["也绝不把内容藏起来"] -.-> Y
```

**为什么没有会话归属就不外置**：一份没有归属的产物，后端没法把它归拢到任何一个会话名下，日后也没人认领——那不如就留在上下文里。

## 一次完整的外置

```mermaid
sequenceDiagram
    participant T as 一件工具
    participant P as 外置策略
    participant S as 文本存储
    participant F as 文件系统接缝
    participant M as 模型
    T->>P: 结果：两百 KB 纯文字
    P->>P: 超过上限，且轮得到我换
    P->>S: 存下这段全文<br/>（带会话归属、工具名、这次调用的编号）
    S->>S: 取 8 个随机字节<br/>会话 id 取哈希<br/>建议名净化
    S->>F: 不覆盖地写下去
    F-->>S: 写成了
    S-->>P: 句柄 ＋ 精确字节数 ＋ 取回说明
    P->>P: 留出说明的位置，切头尾预览
    P-->>M: 开头一截 … 结尾一截<br/>（丢了多少字节。全文存在这里：句柄。取回说明）
```

## 生命周期与并发

```mermaid
flowchart TD
    A["策略不拥有存储"] --> A1["卸载时只撤掉挂在工具注册表上的那一环<br/>存储和已经写下去的产物一概不动"]
    B["每次工具调用各发各的保存请求"] --> B1["存储可以并发调用<br/>它本身不持有任何可变状态"]
    C["并发安全由文件系统接缝负责"] --> C1["「不存在才写」这条由后端保证"]
```

### 存全文用的是一个独立的背景取消上下文

```mermaid
flowchart TD
    A["执行后这一环跑的时候<br/>那次工具调用已经收敛了"] --> B["签名里根本没有那次调用的取消信号"]
    B --> C["所以存全文用一个独立的背景上下文"]
    C --> D["它不该被一次已经结束的调用连累"]
    E["中途被撤掉"] -.->|"只会留下一个存了一半的句柄"| D
```

存储那一侧仍然是收取消上下文的——外置的正是「大到装不下」的那种结果，一次传不完又停不下来的写入，恰恰是这条接缝最容易出的问题。

### 配置错了就让部署起不来

```mermaid
flowchart LR
    A["装载的时候一次性验完"] --> A1["上限是负数：拒"]
    A --> A2["没给存储后端：拒"]
    A --> A3["没给「这次调用属于哪个会话」的映射：拒"]
    B["留到每次调用再验"] -.->|"一份写错的配置<br/>会变成每一次超标调用都失败"| C["该让部署起不来的事<br/>不该让工具挂掉"]
```

存储那一侧同理：没给文件系统、没给根前缀、没给取回说明，三样缺一样就装不出来。

```mermaid
    B -->|"取不到随机字节"| E["不写<br/>宁可失败也不用一个猜得出来的名字"]
    B -->|"键撞上了"| F["报错，不覆盖<br/>在先那份产物一个字都不能少"]
    G["外置成功了，但那句替换文字拼不出来"] --> H["放弃这次替换<br/>已写下的全文成为无害的孤儿"]
```

一条贯穿的规矩：**任何一次退让都不许让模型以为自己看到的是全部**。要么原样给全，要么明说挪走了多少、挪到哪儿去了。

## 能力边界

```mermaid
flowchart TD
    Y["这几个包做的"] --> Y1["判断一份纯文字结果超没超预算"]
    Y --> Y2["把全文逐字存到外部存储"]
    Y --> Y3["原地留下预览、句柄、取回说明"]
    N["不做的"] --> N1["不是键值存储<br/>这条接缝只能写，没有读的方法"]
    N --> N2["不是会话持久化，也不是通用文件上传"]
    N --> N3["不管访问控制、加密、句柄怎么解析"]
    N --> N4["不定保留期，也不做启动清扫"]
    N --> N5["不切预览<br/>头尾截断是保留策略那一层的活"]
    N --> N6["不碰本机磁盘<br/>服务端部署下面接的是对象存储"]
```

最后再说一句最容易被误读的：**外置换来的是更少的上下文占用，不是一份永久对象**。存进去的东西什么时候消失，取决于介质那一侧的保留规则，这几个包一个字都不承诺。
