# 会话读侧（`feature/sessionquery/`）

本文讲这一个包，和它下面唯一的子包 `feature/sessionquery/querytool`。会话日志本身怎么记、怎么存住、怎么折成当前状态不在本文范围内，只在需要说明接缝时点到名字。

```mermaid

    P["产品 / 设计"] --> P1["定位整节<br/>架构里的全景、活的优先、三种表面位置<br/>工具层的工作区边界"]
    D1["研发：要改这个包"] --> D2["全文<br/>引擎层和工具层两节是主体"]
    D3["研发：只是用它"] --> D4["架构<br/>装配顺序<br/>失败语义"]
```

## 定位

### 为什么需要这个东西

会话历史是这个产品最值钱的那份资产——它记着做过什么决定、跑过什么工具、模型说过什么。但一份只能追加、不能修改的流水账，直接摊开来是没法用的。

```mermaid
flowchart LR
    subgraph BAD["把流水账直接摊给调用方"]
        A1["几万条只追加的事件"] --> A2["谁要看回去<br/>谁自己解一遍"]
        A2 -.->|"每个调用方各解各的<br/>解法不一样，答案就不一样"| A1
        A2 -.->|"「模型现在还看得见哪句话」<br/>要重写一遍折叠规则才答得出"| A1
    end
```

```mermaid
flowchart LR
    subgraph GOOD["把它变成人和模型都能用的东西"]
        B1["一次观察"] --> B2["一份逻辑会话<br/>头和事件必然同源"]
        B2 --> B3["精确读 · 过滤 · 追溯 · 表面定位 · 检索"]
        B3 --> B4["人看得懂，模型也查得动"]
    end
```

这个包回答一件事：**已经发生过的会话，怎么被安全地看回去。**

### 产品要做到的七件事

```mermaid
flowchart LR
    U1["列出所有会话<br/>每次列出来的顺序都一样"] --> E1["语料列举"]
    U2["一个会话「还开着」还是「已经存档」<br/>甚至两者同时成立"] --> E2["逻辑会话的两个状态位"]
    U3["按时间段、按父会话、按事件类型筛"] --> E3["纯谓词过滤"]
    U4["「这个会话是谁派出来的<br/>它又派出了谁」这棵树"] --> E4["血统追溯"]
    U5["「模型现在还看得见哪些话<br/>哪些已经被后来的内容盖掉了」"] --> E5["表面定位"]
    U6["按关键词搜整个历史"] --> E6["检索挂点<br/>后端另挂，本包不自带"]
    U7["让模型自己去查历史"] --> E7["那五件工具"]
```

### 一次工具调用的全过程

五件工具的骨架是同一个，顺序不能换：

```mermaid
sequenceDiagram
    participant M as 模型
    participant C as 工具面
    participant E as 引擎
    participant S as 语料

    M->>C: 点名一次事件精读
    Note over C: ① 参数先验<br/>序号和窗口是不是非负
    C->>C: ② 认出调用方<br/>从 agent 钥匙取出会话快照<br/>没有 agent 就报出来
    C->>E: ③ 授权：按身份 + 工作目录 筛
    E-->>C: 恰好一条 = 准；否则一律 UNAUTHORIZED
    C->>E: ④ 真正去读
    E->>S: 装载（活的优先）
    S-->>E: 一份脱离的日志
    E-->>C: 事件 + 上下文窗口
    Note over C: ⑤ 复核<br/>交回来的头必须还是当初批准的那个
    C->>E: ⑥ 读标题
    E-->>C: 标题观察
    C->>M: ⑦ 排成纯文本
```

```mermaid
flowchart TD
    O1["③ 在 ④ 之前"] --> O11["先读了再判断<br/>日志已经读出来了<br/>泄不泄密只剩下「返不返回」这一道<br/>那不够"]
    O2["⑤ 在 ④ 之后"] --> O21["授权和调用之间会话可能被挪出工作区<br/>或者引擎答非所问"]
    O3["① 排在 ② 之前"] --> O31["一个写错的序号<br/>和这次调用是谁发的没关系<br/>先说出来能省掉一整趟授权"]
    O4["⑥ 也要过边界"] --> O41["一次批量标题观察<br/>同样可能捞回一个不该看见的会话<br/>所以标题结果里的每一份头也要复核"]
```

### 活的优先：一份逻辑会话是怎么定下来的

同一个会话身份可能同时有两份东西：内存里正在被推进的那份，和存储里已经落地的那份。

```mermaid
flowchart TD
    START["装载一个身份"] --> LIVE1{"活会话表里有？"}
    LIVE1 -->|"有"| USE1["用活的<br/>根本不问落地那一侧"]
    LIVE1 -->|"没有"| HASP{"挂了落地那一侧吗？"}
    HASP -->|"没挂"| NF["找不到这个会话"]
    HASP -->|"挂了"| LIST["列举落地会话"]
    LIST --> INLIST{"列举里有这个身份？"}
    INLIST -->|"没有"| NF
    INLIST -->|"有"| INSPECT["读出那份落地日志"]
    INSPECT --> LIVE2{"再问一次：<br/>刚才这会儿变活了吗？"}
    LIVE2 -->|"变活了"| USE2["用活的<br/>刚读的那份已经旧了"]
    LIVE2 -->|"没有"| CMP{"两份头对得上吗？"}
    CMP -->|"对不上"| CONFLICT["来源冲突<br/>拒绝，不挑一份用"]
    CMP -->|"对得上"| USE3["用落地的"]
```

```mermaid
flowchart LR
    T1["认出是活的就根本不问落地那一侧"] --> T11["这不是性能优化，是可用性契约<br/>一个可选后端的故障<br/>不该让此刻在内存里的历史读不出来"]
    T2["读完落地的还要再问一次"] --> T21["会话在读取期间被挂起来是平常事<br/>那时候刚读出来的那份已经过时了"]
```

会话头上那条工作目录是一条**执行世界**里的绝对路径。别的包拿它当解析基准去问文件接缝；**本包不碰任何存储**——这里它只参与身份比对和工作区边界那两次字符串相等，仅此而已。

### 引擎的十七个码

| 码说的事 | 谁会报 | 调用方该怎么办 |
|---|---|---|
| 调用被取消 | 引擎各处 | 不用管 |
| 落地日志坏了 | 语料 | **重试没用**，这份存档没救 |
| 后端列举或装载失败 | 语料 | 重试**可能**有用 |
| 找不到这个会话 | 语料 | 换一个身份 |
| 两份来源对不上 | 语料 | 运维的事：两个进程连着同一份介质 |
| 装配参数不合法 | 构造时 | 改装配 |
| 过滤器不合法 | 过滤 | 改参数 |
| 窗口大小不合法 | 事件精读 | 改参数 |

| 上游能力 | DSH 包 | 裁决 | 落在哪个 Go 包 | 这里缺什么 |
|---|---|---|---|---|
| 会话查询Service Definition，提供精确读取、关系跟踪与过滤 | `session-query/session-query` | 需要 | `feature/sessionquery` | — |
| SQLite全文搜索会话查询提供方实现 | `session-query/session-query-sqlite` | 取形重写 | `feature/sessionquery` | 缺口：feature/sessionquery 只定义了 Searcher 挂点，全仓库没有任何实现，两个检索方法一律返回 CodeSearchDisabled。要取的查询表结构与索引形状还没落成 Postgres 版 |
| 经工作区授权的会话查询模型工具 | `session-query/tool-session-query` | 需要 | `feature/sessionquery/querytool` | — |
