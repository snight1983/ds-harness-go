# 计划与待办

## 定位

`plan/planmode` 管理“当前是否先规划后执行”的会话状态，`todo` 管理模型的结构化待办清单。两者都把状态写进 Session 事件并提供投影，但语义不同：计划模式控制请求装配，Todo 记录当前工作项。

## 计划模式

`Controller.Get` 从日志折出当前模式，`Controller.Set` 请求切换。回合外切换立即写入；回合内切换暂存到下一次被接受的 pre-step，避免同一回合的系统提示词和工具表前后矛盾。

退出计划工具始终注册，进入或退出只改变提示词内容，不改变工具表，从而减少模型提示缓存失效。`OnSessionDisposed` 清理尚未落盘的挂起选择。

## Todo

`todo_write` 每次提交完整列表，事件采用 last-wins 折叠。它不提供逐项增删 API，所以每一条事件本身都是可独立解释的当前事实。

`Config.AllowParallelInProgress` 控制调用时是否允许多个进行中项目，但历史不变量不依赖当前配置：过去在宽松策略下写入的日志不能因为今天收紧配置而无法回放。

## 架构

```text
用户 / Exit Plan Tool -> planmode.Controller -> plan/mode 事件
模型 todo_write -------> todo.Tool ----------> todo/write 事件
                                                   |
                                                   v
                                      Projection Registry / 恢复
```

## 生命周期与并发

- 两个模块都通过显式 `Install` 或 `RegisterProjection` 接入，并返回撤销函数。
- 模式与 Todo 的持久状态来自事件日志，内存只保存回合内尚未提交的模式选择。
- 同一 Agent 的事件追加由 Agent Loop 串行化；外部并发调用仍需处理追加失败。
- 投影注册是可选能力，不安装投影不影响事件本身的可恢复性。

## 失败语义

- 非法模式事件、Todo 状态、重复 ID 或策略冲突在追加前拒绝。
- 用户拒绝计划时返回明确 Outcome，不伪装成工具执行失败。
- 切换写盘失败时当前模式保持不变。
- `ValidateEvent` 和不变量注册检查持久历史，而非当前 UI 状态。

## 能力边界

- 计划模式不是文件系统沙箱，也不等同于审批策略。
- Todo 不负责实际调度、依赖图或跨会话同步。
- 计划文本由模型产生，本模块不验证方案质量。
- 是否允许并行进行中项目是部署策略，不是永久日志规则。
