# LLM 测试与回放

对应包：`sessionlog/snapshot`、`feature/replay`、`llm/mockserver`、`cmd/llmmockserver`

## 定位

一套建在模型之上的装置，最难办的事是**它没法照常规办法测自己**。同一句话问两遍，模型答得不一样；今天答得出来，明天限流就答不出来；想让它在第 7 轮的第 3 个分块之后断掉，它不听。

```mermaid
flowchart LR
    subgraph N["直接对着真模型写测试"]
        A1["跑第一遍：绿"] --> A2["跑第二遍：红<br/>它只是换了一种说法"]
        A2 --> A3["查半天，发现代码根本没错"]
        A3 --> A4["于是把断言放宽<br/>一路放到什么都验不出来"]
    end
```

```mermaid
flowchart LR
    subgraph Y["把模型换成一个说话算数的替身"]
        B1["替身每次说同样的话"] --> B2["跑一百遍结果一样"]
        B2 --> B3["红了就是真的红了"]
        B1 --> B4["不要密钥、不花钱、不看网络脸色"]
    end
```

这四个包要摆平的不确定性其实是两种，各走一条路：

```mermaid
flowchart TD
    U["测一套建在模型上的装置<br/>要摆平两种不确定"] --> U1["模型说了什么"]
    U --> U2["线路怎么坏"]
    U1 --> R["回放<br/>把一份录好的转写稿倒回去"]
    U2 --> M["假服务器<br/>按剧本演掉线、限流、半截流"]
    R --> F["而那份转写稿从哪儿来<br/>由快照压制回答"]
```

```mermaid

    P1["快照压制"] -->|"写"| FX[("一份可提交进仓库的<br/>会话转写稿")]
    FX -->|"读"| P2["回放"]
    P3["假服务器"] --> W["线路那一半：走真 HTTP<br/>掉线、限流、SSE 从中间截断"]
    P4["独立进程"] --> W2["同一台假服务器<br/>包成别的进程连得上的服务"]
```

## 架构

```mermaid
flowchart TD
    T["一次测试"] --> Q{"这次要考什么"}
    Q -->|"模型说了什么<br/>循环怎么走、状态机对不对"| RP["回放"]
    Q -->|"线路怎么坏<br/>掉线、限流、半截流"| MS["假服务器"]
    RP --> RIN["装进模型运行时，占住那条路由<br/>整条路根本不碰网络"]
    MS --> MIN["起一台真的本机 HTTP 服务<br/>被测那侧照常发请求"]
    MIN --> CP["要跨进程时，再包一层独立进程"]
    RIN --> FX[("会话转写稿夹具")]
    SN["快照压制"] --> FX
```

四个包各管一段，边界写在「不管什么」上：

```mermaid
flowchart LR
    subgraph A["快照压制"]
        A1["管：把一次真跑<br/>压成两次跑都一样的字节"]
        A2["不管：读写文件、驱动 agent、判对错"]
    end
    subgraph B["回放"]
        B1["管：按录下来的次序<br/>把模型的话吐回去"]
        B2["不管：录、脱敏、评价模型说得对不对"]
    end
    subgraph C["假服务器"]
        C1["管：按剧本在线路上演故障"]
        C2["不管：重试、解释、替调用方做策略判断"]
    end
    subgraph D["独立进程"]
        D1["管：解析参数、绑端口<br/>播报地址与种子、转发遥测、接住信号"]
        D2["不管：模拟行为本身"]
    end
```

**假服务器不替调用方判断该不该重试**，因为那件事一混进来，测试自己就变成一个需要被测试的东西。

### 一个静态文件不可能知道的值

有些值是这一跑当场铸出来的——比如一个随机的目标标识，模型必须把它原样回填。一份写死的转写稿知道不了，于是剧本里埋一个按模式取值的占位符，派流时拿活的请求解算：

```mermaid
sequenceDiagram
    participant A as agent 循环
    participant R as 回放
    participant E as 转写稿里的那一条
    Note over A: 这一跑随机铸了一个新的目标标识
    A->>R: 请求，消息里带着那个标识
    R->>E: 取下一条，里面埋着一个占位符
    R->>R: 把请求里每一个字符串叶子接起来当语料
    R->>R: 按模式匹配，最后一次匹配赢
    R-->>A: 把匹配到的那一段填回占位符，再吐出去
    Note over A: 于是模型「记得」它刚收到的那个标识
```

## 假服务器：让「模型接口坏掉之后怎么办」可以被测

真的供应商不会在你想要的时候掉线、限流、或者把流从中间截断，而这三件事恰恰是恢复策略里最要紧的分支。

### 一次请求走的路

```mermaid

    Q1 -->|"任一道不合格"| E["按普通 4xx 回掉<br/>剧本游标一动不动"]
    E -.->|"一次拼错的地址不该把后面<br/>所有用例的剧本错开一格"| E
    Q1 -->|"全合格"| C["取剧本的下一条"]
```
